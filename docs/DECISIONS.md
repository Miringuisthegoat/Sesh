# Architecture decision log
| # | Date | Decision | Why / trade-off |
|---|---|---|---|
| 1 | 2026-10-31 | Build in phases, each delivered as a zip overlay for the VS Code project folder | User workflow |
| 2 | 2026-10-31 | Conversion: python-docx/openpyxl/Pillow/ReportLab, NO LibreOffice | Spec constraint. Fidelity is limited; go/no-go on real documents in Phase 1 |
| 3 | 2026-10-31 | PDF rasterising for previews/inspection uses pypdfium2 (Apache/BSD) | PyMuPDF is AGPL; avoided |
| 4 | 2026-10-31 | Printing: SumatraPDF CLI (GPLv3), not bundled; located via SUMATRA_PATH or poc\bin | Licence review needed before redistribution |
| 5 | 2026-10-31 | Printer discovery via PowerShell Get-Printer (no pywin32 dependency in PoC) | Fewer dependencies; revisit for agent |
| 6 | 2026-11-01 | Real printer testing deferred; app built first | No printer available now. Phase 1 print script is untested on Windows |
| 7 | 2026-11-01 | Modular monolith: Flask app factory + blueprints (auth, dashboard, admin) + services layer | Spec: no microservices |
| 8 | 2026-11-01 | SQLite default for local dev, PostgreSQL via DATABASE_URL (psycopg 3). Portable types only (sa.Uuid, VARCHAR enums, JSON) | Same migrations run on both; tests also run migrations |
| 9 | 2026-11-01 | Public ids are UUIDv4 columns; integer ids never exposed in URLs | Non-guessable identifiers |
| 10 | 2026-11-01 | One-office/one-agent/one-printer MVP enforced in services via config limits, not schema constraints | Multi-office later = config change, no migration |
| 11 | 2026-11-01 | Cross-company lookups return 404 (not 403) | Do not reveal that a record exists elsewhere |
| 12 | 2026-11-01 | Users are loaded on every request, so deactivation takes effect immediately | Cut-off without waiting for session expiry |
| 13 | 2026-11-01 | Unique login email across the system (lowercased) | Simple sign-in without a company selector; revisit for multi-company |
| 14 | 2026-11-01 | CSP allows only self + cdn.jsdelivr.net (Bootstrap CDN); no inline scripts | Vendor Bootstrap locally in Phase 7 hardening to remove the CDN dependency |
| 15 | 2026-11-01 | Agent secrets stored only as SHA-256 hashes (enrolment token, credential) | DB leak does not leak usable credentials |
| 16 | 2026-11-01 | Print-job and conversion tables exist now; their logic arrives in Phases 3-5 | Schema stable early; no inert UI shipped |
| 17 | 2026-11-01 | Conversion engine copied into `app/conversion/engine/` (from poc/), poc/ left untouched | App must not import from an experiment folder; duplication is accepted until Phase 7 cleanup |
| 18 | 2026-11-01 | Queue = database table (ConvertedFile status QUEUED), atomic claim by conditional UPDATE, polled by `flask run-worker`. Celery/Redis NOT used | Durable, no extra service, works on SQLite and PostgreSQL. Trade-off: polling latency (~2 s) and no built-in scheduling/priorities; a Celery adapter can wrap `process()` later |
| 19 | 2026-11-01 | Worker lease: PROCESSING older than CONVERSION_LEASE_SECONDS is failed as WORKER_LOST and retried; a slow worker cannot publish after losing its lease (conditional UPDATE) | Crash safety without duplicate results. No per-conversion hard timeout yet (would need a subprocess): Phase 7 |
| 20 | 2026-11-01 | Retries: retryable errors create a new ConvertedFile attempt up to MAX_CONVERSION_RETRIES (3 total); invalid/unsupported files fail immediately | No infinite retries; manual 'Try again' only when the last failure was retryable |
| 21 | 2026-11-01 | Files are served only through authorised Flask routes that stream from private storage; no presigned or public URLs | Spec: no permanent public URLs. Cost: PDF bytes pass through the web server |
| 22 | 2026-11-01 | Preview = server-rendered page PNGs (pypdfium2, first MAX_PREVIEW_PAGES pages) + Open/Download PDF; PDF.js not used | Mobile browsers cannot embed PDFs; no vendored JS or CSP/frame-header changes. Cost: CPU per page view, renders on demand (no cache yet) |
| 23 | 2026-11-01 | Upload validation runs twice (upload and worker): extension, MIME consistency, signature, ZIP structure/bomb limits, image header size, OLE/password-protected rejection | Spec: validate again before processing |
| 24 | 2026-11-01 | Visibility: admins see all company documents; workers see their own (or all if company policy `workers_can_view_all_documents`); only owner/admin may retry or remove; everything else returns 404 | Matches spec roles; policy flag already existed from Phase 2 |
| 25 | 2026-11-01 | Delete is soft (deleted_at); stored files are kept until a retention purge (not built yet) | Spec: retain records; retention job arrives in hardening |
| 26 | 2026-11-02 | Phase 4 split: 4a = backend agent API + admin enrolment; 4b = Windows agent app (setup, DPAPI, printers, tray, packaging); job claim/print loop follows Phase 5 server endpoints | Agent cannot download/print jobs until the print-job state machine and claim API exist |
| 27 | 2026-11-02 | Enrolment: admin generates a single-use token (24 h, shown once, hash stored); agent exchanges it at POST /api/agent/v1/register for a long-lived credential (hash stored). No session codes | Spec: secure one-time registration, revocable machine identity |
| 28 | 2026-11-02 | Agent API is bearer-auth JSON under /api/agent/v1, CSRF-exempt (no cookies); human routes keep CSRF | Machine clients cannot do CSRF; credential in header is not ambient |
| 29 | 2026-11-02 | Agent connectivity (last_seen_at) and printer availability (reported per heartbeat; missing = OFFLINE) are separate fields; MVP printer limit enforced when the agent selects printers | Spec: never show printer online just because agent is online |
| 30 | 2026-11-02 | Credential rotation is immediate (old credential dies at once). If the rotate response is lost the agent is locked out and the admin must revoke and re-enrol | Simplicity; an overlap window is a later hardening option |
| 31 | 2026-11-02 | Agent = package `office_agent/`: UI-free core (`agent_service`, `cloud_client`, `local_database`, `secrets_store`, `printer_manager`) plus thin Tk/pystray shell | Core is testable without Windows; the shell is the only untestable part |
| 32 | 2026-11-02 | Tk owns the main thread; pystray runs detached; network calls run in worker threads and post results back | Avoids frozen windows and cross-thread Tk calls |
| 33 | 2026-11-02 | Credential protected with DPAPI (current user) + app entropy, stored base64 in the local SQLite settings; undecryptable -> re-enrol | Spec: DPAPI; no secret in clear on disk |
| 34 | 2026-11-02 | Per-user installer (no admin), data in %LOCALAPPDATA%\SeshAgent kept on upgrade, uninstall asks before deleting it; startup via HKCU Run | Matches 'normal app in the user session'; protects job-recovery state |
| 35 | 2026-11-02 | Server URL: https only (http only for localhost), redirects never followed with the credential; default address baked into server_url.txt at build time | Prevents credential leaks to a redirect target or plaintext transport |
| 36 | 2026-11-02 | Virtual printers (Print to PDF, XPS, OneNote, fax) are listed but labelled; Windows status is a hint, never proof of paper | Truthful status |
| 37 | 2026-11-03 | Phase 5 split in three: 5a server job core (state machine, create, claim, lease recovery, cancel, resolve; this drop), 5b agent job API + agent print loop, 5c web UI (submit, queue, history, admin) | Each part is testable alone; the agent cannot print until 5a's rules exist |
| 38 | 2026-11-03 | Status changes go through one transition table and a conditional UPDATE (`WHERE status = seen`); agents may only set DOWNLOADING, DOWNLOADED, SUBMITTED_TO_PRINTER, COMPLETED, FAILED, UNKNOWN or hand a job back to QUEUED | Illegal or racing updates are refused by the server, not trusted to clients |
| 39 | 2026-11-03 | Claiming = atomic conditional UPDATE plus a one-time claim token (only its SHA-256 stored). Every agent report needs the token and renews the lease | A stale or foreign agent cannot touch a job it does not hold |
| 40 | 2026-11-03 | Lease expiry: CLAIMED/DOWNLOADING -> requeue (after MAX_JOB_ATTEMPTS -> FAILED); DOWNLOADED -> UNKNOWN, never auto-requeued. Attempts are counted from audit rows (no new column) | Printing is a physical side effect: do not risk a duplicate print |
| 41 | 2026-11-03 | Users may cancel only QUEUED/CLAIMED/DOWNLOADING jobs; DOWNLOADED is the point of no return. The agent must print only after the server accepted DOWNLOADED | Cancel can never race with an already started print |
| 42 | 2026-11-03 | UNKNOWN is settled by an administrator ('printed' -> COMPLETED, 'not printed' -> FAILED) or by the original agent proving SUBMITTED. Resubmit always creates a NEW job and is allowed only for FAILED/CANCELLED | No automatic reprint; COMPLETED only with a reliable signal |
| 43 | 2026-11-03 | Agent job API under /api/agent/v1/jobs: claim, pdf (X-Claim-Token header), status, lease. 404 JOB_NOT_FOUND hides unknown/foreign/wrong-token jobs; 409 JOB_CANCELLED / ILLEGAL_TRANSITION carries job_status | Agent can always tell 'stop, do not print' from 'try later' |
| 44 | 2026-11-03 | Agent journals every stage locally (write-ahead); SUBMITTING is written before the print command; the claim token is stored DPAPI-protected | A crash can never cause a blind reprint |
| 45 | 2026-11-03 | Recovery: CLAIMED/DOWNLOADING -> hand back; DOWNLOADED -> FAILED AGENT_RESTARTED; SUBMITTING -> UNKNOWN; SUBMITTED -> resend report. DOWNLOADED is journalled before it is reported, so a crash in between is settled as FAILED, never printed | Conservative: user may have to resubmit, but no duplicates |
| 46 | 2026-11-03 | SumatraPDF: cannot start or non-zero exit -> FAILED; timeout/other failure after start -> UNKNOWN; not installed -> agent takes no jobs. Not bundled | Truthful status; licence review still open |
| 47 | 2026-11-03 | Before printing the agent re-reads Windows printers; not installed, not enabled or reported OFFLINE -> FAILED PRINTER_UNAVAILABLE (no silent waiting) | Fast, honest feedback; Windows' ERROR status is only a hint so it does not block |
